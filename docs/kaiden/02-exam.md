- 所要時間: 2〜3時間
- 先に読む公式ページ: [How to build with System One](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)
- この章でできるようになること: 学んだことを、自分の手でコードにして証明する

## 10問の関数を書けば、テストが採点する

<!-- freshness: evergreen -->

10問の「穴あきの関数」を、自分で書いて埋めます。自動のテストが採点します。
全部正解すれば**免許皆伝**です。APIキーはいりません。

```bash
npm run exam   # 採点
```

問題は [exam/tasks](../../exam/tasks) にあります。各ファイルの先頭のコメントが問題文です。`throw new Error("未実装")` の行を消して、関数を書いてください。

| 問 | 範囲 | 書くもの |
|---|---|---|
| 第1問 | 二段 | 担当部署の Choice（逃げ道つき） |
| 第2問 | 初段 | 名前付きフィールドの state |
| 第3問 | 三段 | 3レーンの振り分けと、救護への通知 |
| 第4問 | 四段 | 重みづけの優先度と、重みでは動かない「重大な条件」 |
| 第5問 | 五段 | 送る前に電話番号とメールを隠す |
| 第6問 | 六段 | Cohen の κ |
| 第7問 | 七段 | 目標の正解率を満たす最小のしきい値 |
| 第8問 | 九段 | 同時実行数と予算を守る処理 |
| 第9問 | 奥義 | Score の答えの形の検査 |
| 第10問 | 総合 | 記録済みの応答を使った仕分け |

| 得点 | 段位 |
|---|---|
| 10 | 免許皆伝 |
| 8〜9 | 師範代 |
| 5〜7 | 有段者 |
| 0〜4 | 修行中 |

<details><summary>もっと深く（プロ向け）</summary>

- 失敗の理由は `npx vitest run --project exam` で見られます。テスト（[exam/tests](../../exam/tests)）を読むのも立派な勉強です
- 解答例は [exam/solutions](../../exam/solutions) にあります。**全部解くまで開かないこと**。`npm run exam -- --solutions` で解答例を採点すると、10点になることを確かめられます
- 第10問は実APIを呼びません。記録済みの応答（`fixtures/board-ja`）で動きます

</details>

## 本当の皆伝は、自分の業務のデータでやり直せたとき

<!-- freshness: evergreen -->

試験に受かっても、それはこの掲示板での話です。
本当の免許皆伝は、**自分の業務のデータで、同じことをやり直せたとき**です。

自分の題材でやり直す手順:

1. 自分の業務の判断を1つ選び、コードに残す部分と Jev に渡す部分を分ける（五段）
2. 実際のデータから50件以上を取り出し、ガイドを書いてラベルを付ける（六段）
3. 質問を設計し、測り、書き方を直して、また測る（二段・七段）
4. 日本語で使うなら、日英の差を測る（八段）
5. しきい値を決めて3レーンに分け、バージョンを固定して運用する（三段・九段）
6. 「確かめられたこと」と「わかっていないこと」を分けて、他の人に説明する（奥義）

<details><summary>もっと深く（プロ向け）</summary>

- この教材で学んだこと（質問の形の使い分け、基準の書き方、迷いの振り分け、評価用のデータ、実測、本番の守り）を、自分の題材で1つずつ説明できるかを確かめてください
- 自分の題材の測定結果は、`npm run okugi` と同じ要領で、形の性質と観察を分けて記録しておくと、モデル更新のときの比較に使えます

</details>
