# 二段 instructions と criteria

- 所要時間: 30分
- 先に読む公式ページ: [Primitives](https://docs.typesafe.ai/primitives) / [Advanced primitives](https://docs.typesafe.ai/primitives/advanced)
- この章でできるようになること: 質問の書き方で答えが変わることを実験で確かめ、JSON 構造で定義・例外を指定できる

## 聞き方で答えは変わる

🟢 恒久

### ひとことで

「苦情？」とだけ聞くのと、「困りごとや改善の要望が書かれていたら苦情です。遠回しな言い方や皮肉も含みます」と説明してから聞くのとでは、答えが変わって当然です。
人間でも、基準を言われないと判断がぶれます。

### ちゃんと言うと

[src/steps/d2-instructions.ts](../../src/steps/d2-instructions.ts) は、同じ投稿に3通りの書き方で聞きます。

| | 書き方 |
|---|---|
| v1 | `noul("苦情？")` |
| v2 | 文章の質問 ＋ はい/いいえの意味（7級と同じ） |
| v3 | 定義・含むもの・含まないものを **JSON で構造化** |

```ts
export const structured = noul(
  {
    task: "この投稿が、運営に対する苦情や不満かどうかを判断する",
    definition: "書き手が困っている、不満がある、または改善を求めている",
    include: ["遠回しな要望（〜だとうれしいのですが）", "皮肉（さすが運営ですね）", "丁寧な言葉づかいの要請"],
    exclude: ["純粋な質問", "お礼や感想", "落とし物などの報告"],
  },
  { true: "苦情や不満、改善の要望", false: "それ以外" },
);
```

対象の投稿は、遠回しな要望（p08）・皮肉（p14）・とても丁寧な要請（p51）・丁寧な質問（p13）です。

```bash
npm run d2
```

<details><summary>もっと深く（プロ向け）</summary>

- 公式スキルは「単純な質問は文字列でよい。定義・対比・除外・例が指示を明確にするなら、構造化したオブジェクトや配列を使う」としています
- 1つの質問には、狭く一貫した判断を1つだけ入れます。「苦情で、かつ急ぎですか？」のように2つを混ぜると、どちらの意味の確率なのかわからなくなります
- 書き方を変えたら、七段の測定をやり直して確かめます。1件の見た目で判断しないでください
- replay の数字は見本です。「v3 がいちばん高い」ように見えても、実APIでそうなるとは限りません

</details>

## 「どれにも当てはまらない」を用意する

🟢 恒久

### ひとことで

選択肢に「その他」がないと、関係のない宣伝の投稿でも、無理やりどこかの係に振られてしまいます。

### ちゃんと言うと

6級の担当部署の質問には、逃げ道がありませんでした。二段の後半は、同じ宣伝の投稿（p25）を「sonota なし」と「sonota あり」の2つの質問で比べます。

```ts
sonota: "どれにも当てはまらない。お祭りと関係のない宣伝など",
```

この逃げ道を足した質問を、三段以降の「本番用」の質問として [src/lib/board.ts](../../src/lib/board.ts) にまとめています。

<details><summary>もっと深く（プロ向け）</summary>

- 公式スキルは「何も当てはまらないことがありうるなら、no-match の選択肢を入れる」としています
- 逃げ道がない Choice は、確率が特定のラベルに寄っていても「消去法の1位」のことがあります。confidence が低いかどうかも合わせて見ます（三段）
- 「当てはまるものがあるか」自体が独立して役に立つなら、Choice とは別の Noul で聞く方法もあります

</details>
