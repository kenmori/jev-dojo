# 八段 日本語ラボ

- 所要時間: 60分
- 先に読む公式ページ: [Models](https://docs.typesafe.ai/models)（言語サポートの記述） / [Model jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
- この章でできるようになること: 同じ課題を日英で流し、精度の差を自分の手で測れる。日本語で使うときのしきい値を自分のデータで決められる

## 公式の指示に文字通り従う

<!-- freshness: evergreen -->

公式ドキュメントは「英語がいちばん得意。日本語などほかの言語も扱えるが、同じとは限らない。英語以外で使うなら、自分の文章でテストすること」と言っています。
この章は、その指示どおりにテストする作業です。

60件の投稿を、日本語と、同じ内容の英訳の両方で判定し、次を比べます。

- ラベルに対する精度（苦情・担当・緊急度）
- confidence の分布
- 日英で答えが一致した割合
- 言い回し別（敬語・主語省略・婉曲・皮肉）の精度
- 日英で答えが食い違った投稿そのもの

```bash
npm run d8
```

レポート: [_generated/lab-ja-en.md](../_generated/lab-ja-en.md)

**いま入っているのは、作者が1回だけ記録した実APIの応答です。** 自分の環境で測り直すには、APIキーを入れて次を実行します。

```bash
npm run record d8   # 日英120件を実APIで判定して記録
npm run reports     # レポートを作り直す
```

<details><summary>もっと深く（プロ向け）</summary>

- 英語は日本語から訳したもので、専門の翻訳者によるものではありません。訳し方（敬語や皮肉のニュアンスが英語でどう出るか）が結果に影響している可能性があります。気になる投稿は訳を直して測り直してください
- 日英で答えが食い違った投稿は、どちらの言語で間違えたのかをラベルと照らして見ます。食い違い＝日本語が悪い、ではありません
- 結果は `docs/_generated/eval-history.md`（週次のライブ評価）と合わせて、モデルの更新のたびに取り直します

</details>

## 悪い数字が出たら、まず質問の設計を疑う

<!-- freshness: evergreen -->

日本語の数字が悪くても、すぐに「Jev は日本語に弱い」と結論しないでください。
多くの場合、原因は質問の書き方のほうにあります。

1. 食い違った投稿を並べ、タグ（敬語・主語省略・婉曲・皮肉）に偏りがないかを見る
2. 偏りがあれば、その言い回しを criteria の `include` に書き足す（二段）
3. 同じ60件で測り直す（七段）
4. 変えたことと数字の変化を記録する

**設計を変えて測り直すところまでが、この章の作業です。**

<details><summary>もっと深く（プロ向け）</summary>

- 60件では、統計的に強いことは言えません。1件で割合が数ポイント動きます。「傾向」までにとどめ、件数と限界を必ず書き添えます
- 誇張した結論を書くと、教材全体の信頼を失います。数字は必ず再現コード（`npm run d8`）とセットで示します
- 公式は、バージョンごとの既知の弱点（jaggedness）を公開しています。まずそこに日本語や言い回しの話がないかを確認します

</details>
