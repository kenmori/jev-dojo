# 七段 キャリブレーションを測る

- 所要時間: 45分
- 先に読む公式ページ: [Machine learning primer](https://docs.typesafe.ai/introduction/machine-learning-primer) / [Classification using confidence](https://docs.typesafe.ai/cookbooks/classification_using_confidence)
- この章でできるようになること: Brier score と信頼度曲線を読める。しきい値を勘ではなく測定で決められる

## 「80% と言ったら、80% 当たるか」

🟢 恒久

### ひとことで

天気予報が「降水確率80%」と言った日を集めて、本当に10日のうち8日くらい雨が降ったなら、その予報は信用できます。
これをキャリブレーション（較正）が取れている、と言います。

### ちゃんと言うと

| 指標 | 意味 | よい値 |
|---|---|---|
| 正解率 | 0.5 で切ったときに当たった割合 | 高いほど |
| Brier score | (確率 − 正解なら1、外れなら0)² の平均 | 0 に近いほど。いつも 0.5 と答えると 0.25 |
| ECE | 確率をビンに分け、「言った確率」と「実際の割合」のずれを平均したもの | 0 に近いほど |
| 信頼度曲線 | 横軸に予測した確率、縦軸に実際の割合 | 対角線に近いほど |

```bash
npm run d7
```

計算は [src/lib/metrics.ts](../../src/lib/metrics.ts) にあり、すべて APIキーなしでテストされています。

レポート: [_generated/calibration.md](../_generated/calibration.md)

<details><summary>もっと深く（プロ向け）</summary>

- 正解率が高くても、確率が当てにならない（キャリブレーションが悪い）ことがあります。しきい値で自動化するなら、見るべきは確率の信頼性です
- 公式スキルは「System One モデルは較正された判断をするよう訓練されているが、対象の領域で性能を検証すること」としています。検証するのがこの章です
- ビンの件数が少ないと、信頼度曲線の点は大きく揺れます。60件を5ビンに分けると、1ビン数件のこともあります

</details>

## しきい値を測定で決める

🟡 半恒久

### ひとことで

7級では「0.8 以上なら自動」と仮に決めました。
ここでは「自動で決めたものは95%以上当たってほしい」という目標から逆算して、しきい値を決めます。

### ちゃんと言うと

`npm run d7` は、しきい値 t を動かしたときの表を出します。

- p ≥ t なら「苦情」、p ≤ 1 − t なら「苦情ではない」と自動で決める
- その間は人に回す

| しきい値 | 自動で決めた割合 | そのうち正解 |
|---|---|---|
| 上げると | 減る（人の手間が増える） | 上がる（はず） |

目標の正解率を満たす最小のしきい値が、手間と正確さの釣り合う点です。

> replay で表示される数字は、手で作った見本データから計算したものです。この表から Jev の性能について結論しないでください。

<details><summary>もっと深く（プロ向け）</summary>

- 目標の正解率は、誤判定のコストで決めます。苦情の見落としが高くつくなら、「苦情ではない」側のしきい値だけを厳しくする、という非対称な設計もありえます
- しきい値は**モデルのバージョンごとに**測り直します。これがバージョンを固定する理由です（九段）
- 公式のクックブックに出てくるしきい値やデモの結果は、評価すべき例であって、どこでも通用するルールではありません（公式スキル）

</details>
