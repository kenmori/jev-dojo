# 六段 評価データセットを作る

- 所要時間: 60分（ラベル付けを含む）
- 先に読む公式ページ: [Machine learning primer](https://docs.typesafe.ai/introduction/machine-learning-primer)
- この章でできるようになること: 「何が正解か」を自分で定義し、50件以上にラベルを付けられる。ラベルのぶれを数字で測れる

## 正解は自分で決めるもの

<!-- freshness: evergreen -->

「この投稿は苦情？」に、世界共通の正解はありません。
「花火の音で赤ちゃんが起きてしまいました。もう少し早く終わるとうれしいのですが」を苦情と呼ぶかどうかは、運営の方針で決まります。
Jev の精度を測る前に、まず**自分たちの正解**を決めて書き残します。

データは [data/posts.ja.json](../../data/posts.ja.json) の60件です。同じ内容の英訳が [data/posts.en.json](../../data/posts.en.json) にあり、八段で使います。

作者が付けた例が [data/labels.json](../../data/labels.json) にあります。**これは正解ではなく、下のガイドに沿った1人の判断**です。

```bash
npm run label   # 1件ずつラベルを付ける。途中でやめても続きから
npm run d6      # データの内訳と、作者の例との一致度を表示
```

自分のラベルは `data/labels.mine.json` に保存され、七段・八段で自動的に使われます。

<details><summary>もっと深く（プロ向け）</summary>

- 60件は「傾向を見る」ための最小限の規模です。本番で使う前には、実際の投稿から数百件を無作為に取り出してラベルを付けます
- 評価データは、Jev の出力を見る**前に**付けます。先に答えを見ると、それに引きずられます
- 投稿の偏り（苦情が少ない、救護は7件しかない、など）は、そのまま測定の弱さになります。少ないクラスの数字は大きく揺れます

</details>

## 迷う投稿のために、ラベルの基準を文章にしておく

<!-- freshness: semi-stable -->

判断に迷う投稿のために、ルールを文章にしておきます。ルールがないと、同じ人でも日によって判断が変わります。

**苦情（isComplaint）**

- はい: 困っていること・不満・改善の要望が書かれている。遠回しな言い方（「〜だとうれしいのですが」）、皮肉（「最高のお祭りですね」）、丁寧な要請も含む
- いいえ: 質問・お礼・感想・落とし物の報告・宣伝
- 会場や設備の危険の報告（「提灯が落ちそう」）は、改善を求めているので「はい」
- 人の体調やけがの知らせ（「人が倒れている」）は、運営への不満ではなく助けを求めているので「いいえ」。急ぎ度で扱う

**担当（department）**

| ラベル | 対象 |
|---|---|
| honbu | 全体の予定、ボランティア、ごみ、トイレ、案内、お礼や一般的な意見 |
| yatai | 出店の有無、料金、食べ物、屋台の設備 |
| kotsu | 車、自転車、道路、バス、通行止め、車椅子の道順 |
| otoshimono | なくした物、拾った物、逃げたペット |
| kyugo | けが、体調不良、迷子、危険な状況 |
| sonota | お祭りと関係のない投稿 |

**緊急度（urgency）**

| 段階 | 目安 |
|---|---|
| 2 | 人の安全や体調にかかわり、今すぐ対応が必要 |
| 1 | いま困っている人がいる、または放っておくと悪化する。今日中に対応したい |
| 0 | 後日の対応や、手の空いたときの返信でよい |

**タグ（八段で使う）**: 敬語、主語省略、婉曲、皮肉。当てはまるものを付ける（作者の例のみ）。

<details><summary>もっと深く（プロ向け）</summary>

- ガイドを書いたら、2人で同じ投稿にラベルを付け、一致度（Cohen の κ）を測ります。`npm run d6` は、あなたのラベルと作者の例の κ を出します
- κ が低い項目は、Jev の問題の前にガイドの問題です。食い違った投稿を並べ、ルールを足してから付け直します
- このガイドは、そのまま Jev の criteria の下書きにもなります（二段）。人に説明できない基準は、Jev にも伝わりません

</details>
